## 0. 한 줄 요약

> **빠른 차량은 더 빠르게, 위험한 차량은 확실하게 멈춘다.**
>
> 장물·통관 리스크는 **절대 넘을 수 없는 게이트(Hard Gate)** 로 막고,
> 증빙 보완은 **기한부 조건부 선적(Soft Gate)** 으로 풀어주되 사후 증빙을 시스템이 끝까지 추적한다.
> 회계팀은 200대를 모두 보지 않고, **시스템이 걸러준 차량과 그 차량의 부가세 영향 금액**만 본다.

## 1. 문제 정의

### 1.1 표면의 갈등

| | 영업 총괄 | 회계 팀장 |
|---|---|---|
| 요구 | 매집 당일 인보이스·선적 | 증빙 매칭·압류/도난 확인 전 선적 불가 |
| 두려움 | 시세 하락, 선적 지연 | 부가세 손실, 영세율 오류, 장물 유통, 외부감사·세무조사 |

### 1.2 진짜 원인

1. **모든 차량을 같은 강도로 검토한다** — 문제없는 165대도 문제 있는 7대와 똑같이 사람이 본다 → 느림
2. **리스크의 종류를 구분하지 않는다** — "장물일 수 있는 차"와 "계산서가 하루 늦게 오는 차"가 같은 '보류'로 묶인다 → 영업은 전부 풀어달라, 회계는 전부 막겠다
3. **막힌 이유와 영향이 보이지 않는다** — 엑셀에서는 어떤 차가 왜 막혔고, 그대로 두면 얼마를 잃는지 알 수 없다 → 회계는 불안해서 전부 막는다
4. **"나중에 맞추자"를 강제할 장치가 없다** — 사후 보완이 사람의 기억에 의존 → 회계가 선허용을 신뢰할 수 없다

### 1.3 해결 방향

| 원인 | 해결 |
|---|---|
| 1 | 자동 검증 → 정상 차량은 일괄 처리, 문제 차량만 사람에게 |
| 2 | 리스크를 **Hard Gate / Soft Gate** 로 등급화 |
| 3 | 차량마다 **차단 사유 + 다음 행동 + 예상 부가세 손실 금액** 표시 |
| 4 | 조건부 선적 시 **증빙 기한·책임자·페널티**를 시스템이 관리 |

## 2. 설계 원칙

1. **상태가 곧 업무 권한** — 버튼 비활성화가 아니라, 상태 전이 규칙 자체가 다음 업무 진입을 막는다.
2. **진행 단계와 리스크 판정은 별개의 축** — "선적은 끝났지만 증빙은 미완"을 표현할 수 있어야 한다.
3. **증빙 존재 ≠ 증빙 검증 완료** — 파일이 올라온 것과 회계가 확인한 것을 구분한다.
4. **"왜 막혔는지"와 "무엇을 하면 풀리는지"를 함께 보여준다.**
5. **리스크는 금액으로 말한다** — 회계 팀장에게는 '경고'보다 '공제 못 받을 매입세액 ₩1,363,636'이 설득력 있다.
6. **시스템은 세법을 판단하지 않는다** — 세무 요건은 회계팀이 소유하는 **규칙 테이블**로 두고, 시스템은 규칙대로 선별·알림만 한다.
7. **AI는 판단자가 아니라 검증 보조자** — 문서 추출·대조까지만, 최종 판단은 사람.
8. **모든 예외는 기록된다** — 누가, 왜, 언제까지 보완하기로 하고 풀어줬는지 Audit Trail에 남는다.

## 3. 리스크 게이트 설계 (핵심)

### 3.1 게이트 강도

| 강도 | 의미 | 우회 | 표시 |
|---|---|---|---|
| **Hard Gate** | 회사 존립·법적 문제로 직결. 해소 전 다음 단계 진입 불가 | **불가** (결재로도 못 푼다) | 🔴 차단 |
| **Soft Gate** | 돈(부가세)·서류 문제. 사후 보완 가능 | **조건부 선적** (결재 + 기한 + 책임자) | 🟡 보완 |
| **Clear** | 모든 필수 조건 충족 | — | 🟢 정상 |

> 회계 팀장이 "단 1대도 안 된다"고 한 **VIN 압류·도난**과 **매입 사실 확인 불가**는 전부 Hard Gate.
> 영업 총괄이 "나중에 맞추자"고 한 **서류 보완**은 Soft Gate — 단, 시스템이 기한을 강제한다.

### 3.2 게이트 항목

| # | 검증 항목 | 판정 시점 | 강도 | 해소 조건 |
|---|---|---|---|---|
| H1 | VIN 압류·저당 존재 | 매입 등록(VIN 입력 즉시, 등록 차단) · 선적 직전 재조회 | 🔴 Hard | 해제 증빙 업로드 + 재조회 정상 |
| H2 | VIN 도난 조회 결과 해당 | 매입 등록(등록 차단) · 선적 직전 재조회 | 🔴 Hard | 해소 불가 → 거래 중단 |
| H3 | VIN 조회 미실시 / 결과 만료 | 수출 검증 | 🔴 Hard | 조회 실행 |
| H4 | 차량 실물 인수 미확인 (인수자·차량번호·사진) | 매입 확정 | 🔴 Hard | 인수 완료 처리 |
| H5 | 매도인 신원 미확인 (신분증/사업자등록증 없음) | 매입 확정 | 🔴 Hard | 신원 증빙 업로드·검증 |
| H6 | 수출신고필증 VIN ≠ ERP VIN | 선적 처리 | 🔴 Hard | 필증 정정 후 재대조 |
| H7 | 수출신고 수리 전 | 선적 처리 | 🔴 Hard | 수리 완료 |
| H8 | 선적 전표 결재 미승인·반려 | 선적 처리 | 🔴 Hard | 결재 승인 |
| S1 | 매입세액 공제 증빙 누락 (세금계산서 미수취 등) | 수출 검증 | 🟡 Soft | 증빙 업로드·검증 (기한 내) |
| S2 | 매입 유형 ↔ 증빙 유형 불일치 (딜러 매입인데 영수증만 등) | 매입 등록 · 수출 검증 | 🟡 Soft | 올바른 증빙 수취 또는 회계 판정 |
| S3 | 증빙 금액 ≠ 매입 금액 | 수출 검증 | 🟡 Soft | 정정 증빙 또는 회계 판정 |
| S4 | 개인 매입 반복 매도인 (동일인 N대 이상/월 → 사업자 의심) | 매입 등록 | 🟡 Soft | 회계 검토·판정 |
| S5 | 역마진 거래 (판매가 < 매입가) | 판매 등록 | 🟡 Soft | 결재 시 사유 필수 |
| S6 | 통관·선적 부가정보 누락 (관세사, 예정 선적일 등) | 선적 전표 | 🟡 Soft | 정보 입력 |
| S7 | AI 문서 대조 불일치 (차량번호·금액 등 VIN 외 항목) | 수출 검증 | 🟡 Soft | 원본 확인 후 정정 |

> 규칙값(N대, 기한 일수, 한도 등)은 **회사 정책 설정값**으로 두고 회계팀이 소유한다.

### 3.3 조건부 선적 & 사후 증빙 강제 로직

```text
Soft Gate 차량
   ↓
[조건부 선적 요청] — 영업 담당
   · 보완할 항목 (자동 채움)
   · 보완 기한 (정책 기본값 D+7, 단축만 가능)
   · 보완 책임자
   · 예상 부가세 영향 금액 (자동 계산)
   ↓
[회계 팀장 개별 결재] — 승인 / 반려
   ↓ 승인
선적 진행 가능 (Hard Gate는 여전히 모두 통과해야 함)
   ↓
사후 증빙 추적 (D-day 카운트다운)
   ├─ 기한 내 보완·검증 완료 → 리스크 해소, 종결 가능
   └─ 기한 초과
        · 책임 영업 담당의 신규 조건부 선적 요청 차단
        · 회계 팀장·관리자 에스컬레이션 알림
        · 부가세 신고 마감 전 미해결 목록에 고정 노출
```

**통제 장치**

- **조건부 선적 한도** — 담당자별 미해소 조건부 선적 건수·금액 상한 (정책값). 한도 초과 시 추가 요청 불가.
- **미해소 건은 종결 불가** — 선적이 끝나도 차량은 `사후 보완 중` 단계에 머문다. 증빙이 검증되어야 `종결`.
- **부가세 신고 기간 연동** — 신고 마감 D-14부터 미해소 건과 예상 손실 합계를 회계팀 작업 큐 최상단에 고정.

> 영업에게는: "Soft 사유로는 선적이 멈추지 않습니다."
> 회계에게는: "풀어준 건은 전부 기한·책임자·금액과 함께 추적되고, 안 지키면 그 담당자는 다음 선허용을 못 받습니다."

## 4. 매입·매출 크로스체크 & 부가세 손실 방지

### 4.1 왜 수출업에서 '증빙 = 돈'인가

- 직수출 매출은 **영세율(0%)** → 매출세액이 없다.
- 따라서 매입 시 부담한 부가세는 **적격 증빙이 있어야만 공제·환급**된다.
- 증빙이 없으면 그 매입세액은 **환급받지 못하고 그대로 비용** → 이것이 회계 팀장이 말하는 "부가세 손실".
- 반대로 영세율 적용 요건(수출 사실 증빙)을 갖추지 못하면 **10% 과세로 전환**되어 추징 위험.

> 즉 회계 팀장의 두 걱정(매입 증빙, 영세율)은 **차량 1대마다 금액으로 환산**할 수 있다.

### 4.2 매입 유형별 필요 증빙 (회사 규칙 테이블 — 세무 검토 전제)

| 매입 유형 | 매도인 | 필수 증빙 | 공제 근거(가정) | 예상 공제액 계산 |
|---|---|---|---|---|
| 딜러 매입 | 사업자 | 세금계산서, 매매계약서 | 일반 매입세액 공제 | 공급가 × 10% |
| 경매 매입 | 경매장 | 경매장 발행 세금계산서, 낙찰 확인서 | 일반 매입세액 공제 | 공급가 × 10% |
| 개인 매입 | 비사업자 개인 | 매매계약서, 매도인 신분증 사본, 대금 계좌이체 내역, 자동차 양도 서류 | 중고자동차 매입세액 공제 특례(의제매입) | 매입가 × 10/110 |

> ※ 개인 매입 공제 특례의 적용 요건·공제율은 **세무 자문으로 확정할 영역**이며, 시스템은 이 테이블을 설정값으로 읽는다.

### 4.3 크로스체크 시나리오 & 알람

| 상황 | 판정 | 알람 대상 | 화면 메시지 예 |
|---|---|---|---|
| 딜러 매입인데 세금계산서 없이 현금 영수증만 | 🟡 S2 | 회계 | "딜러 매입은 세금계산서가 필요합니다. 현재 증빙으로는 매입세액 ₩1,500,000 공제 불가" |
| 세금계산서 공급가 ≠ 매입 등록 금액 | 🟡 S3 | 회계·매입 | "증빙 금액 14,500,000 / 등록 금액 15,000,000 — 차액 500,000" |
| 개인 매입인데 계좌이체 내역 없음(현금 지급) | 🟡 S1 | 회계 | "현금 지급 개인 매입 — 공제 요건 서류 부족, 예상 공제액 ₩1,363,636 미확보" |
| 동일 개인 매도인 이번 달 3대째 | 🟡 S4 | 회계 | "개인 명의 반복 매도 — 사업자(위장 개인매입) 여부 확인 필요" |
| 매출 처리 = 영세율인데 수출신고 수리 전 선적 시도 | 🔴 H7 | 물류·영업 | "수출신고 수리 전에는 선적 처리할 수 없습니다" |
| 수출 → 국내 판매로 전환 | 🟡 | 회계 | "국내 판매 전환 — 영세율 대상에서 제외, 10% 과세 매출로 처리됩니다" |

### 4.4 예상 부가세 손실 금액

- 차량마다 **"확보된 매입세액 / 미확보 매입세액"** 을 표시한다.
- 작업 큐·결재 화면에서 **미확보 합계**를 보여준다 → 회계 팀장이 "얼마짜리 리스크를 풀어주는지" 알고 결재한다.
- 계산은 4.2 규칙 테이블 기준 (mock).

### 4.5 역마진 거래 (보조)

- 판매가(원화 환산) < 매입가 → 🟡 S5, 차단하지 않고 결재 사유 필수.
- 환율은 판매 등록 시점 mock 환율 고정 저장.

## 5. VIN 검증

- **시점 2회**: 매입 등록 시 VIN 입력 즉시 조회 / 선적 처리 직전 재조회 (압류는 매입 후에도 새로 걸릴 수 있음).
- **결과 유효기간**: 조회 후 N일 경과 시 만료 → H3.
- **판정**
  - 🟢 이상 없음
  - 🔴 압류·저당 — 압류·저당이 남아 있으면 수출 말소등록이 불가하므로 어차피 수출할 수 없다 → Hard
  - 🔴 도난 — 거래 중단, 해소 불가
  - 🟡 조회 실패/응답 없음 — 재조회 요청
- 실제 외부 조회 API는 생략하고 mock 응답으로 대체한다.

## 6. 상태 모델 (두 개의 축)

### 6.1 진행 단계 (Stage) — 차량이 업무상 어디에 있는가

```text
매입 등록 → 인수 완료 → 매입 확정 → 판매 등록 → 수출 검증 → 선적 전표 → 결재 승인 → 선적 완료 → (사후 보완 중) → 종결
```

### 6.2 리스크 판정 (Risk) — 지금 무엇이 걸려 있는가

- `CLEAR` 🟢 / `REVIEW` 🟡 (Soft Gate 존재) / `BLOCKED` 🔴 (Hard Gate 존재)
- 차량의 Risk는 **걸려 있는 게이트 항목들로부터 계산**된다 (저장값이 아니라 파생값).

### 6.3 전이 규칙

| 전이 | 조건 |
|---|---|
| 매입 등록 → 인수 완료 | 인수자·차량번호 확인·사진 업로드 |
| 인수 완료 → 매입 확정 | H1·H2·H4·H5 통과 |
| 매입 확정 → 판매 등록 | 매입 확정 차량만 선택 가능 |
| 판매 등록 → 수출 검증 | 자동 실행 |
| 수출 검증 → 선적 전표 | Risk = CLEAR → 일반 편입 / REVIEW → **조건부 선적 결재 승인 시** 편입 / BLOCKED → 불가 |
| 선적 전표 → 결재 승인 | 전표 결재 승인 |
| 결재 승인 → 선적 완료 | H1·H2 재조회 통과, H6·H7 통과 |
| 선적 완료 → 종결 | 미해소 Soft 항목 없음 (있으면 `사후 보완 중`) |

## 7. 결재 정책

- **정상 차량**: 선적 전표 단위 **일괄 결재** (영업 속도 확보).
- **조건부 선적 차량**: 차량 단위 **개별 결재** — 회계 팀장. 보완 항목·기한·책임자·예상 부가세 영향이 결재 화면에 함께 표시.
- **역마진 거래**: 결재 사유 필수.
- 반려 시 사유 필수 → 차량은 수출 검증 단계로 되돌아감.

## 14. 회계 팀장 설득 시나리오 (시연 순서)

1. **"VIN 한 번 입력해 보시죠."** — 압류 차량(F)은 매입 등록 버튼부터 막힌다. 결재로도 못 푼다는 것을 보여준다.
2. **"딜러 매입인데 영수증만 있는 차입니다."** — 매입 등록 화면에서 즉시 경고 + 미확보 매입세액 금액.
3. **"200대를 다 보실 필요 없습니다."** — 작업 큐에서 회계가 볼 차량만, 금액 순으로.
4. **"영업이 먼저 보내달라고 한 차입니다."** — 조건부 선적 결재 화면: 무엇을, 언제까지, 누가, 얼마짜리인지. 승인/반려는 팀장님 권한.
5. **"약속을 안 지키면?"** — 기한 초과(J): 해당 담당자는 다음 선허용이 막히고, 신고 마감 전 목록에 고정.
6. **"감사인이 물으면?"** — 차량 상세 Audit Trail: 누가 언제 왜 풀어줬는지 전부.

**영업 총괄에게는**: 정상 차량은 일괄 결재로 당일 선적, Soft 사유로는 선적이 멈추지 않음, 막히는 건 법적으로 어차피 못 나가는 차뿐.
